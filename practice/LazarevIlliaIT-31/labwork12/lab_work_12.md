# Практична робота №12
## Сортування та фільтрація даних
**Варіант 7 — спортивний зал / фітнес-клуб**

### Мета роботи
Навчитися сортувати записи за однією та кількома колонками за допомогою `ORDER BY`, обмежувати кількість результатів через `LIMIT`, прибирати дублікати за допомогою `DISTINCT` і застосовувати умови `IN` та `LIKE`.

У роботі використано таблиці:
- `membership_sales` — фактичні продажі абонементів;
- `memberships` — типи абонементів;
- `clients` — клієнти фітнес-клубу.

### Завдання 1. ORDER BY за однією колонкою
Використано запит:
```sql
SELECT id, membership_id, client_id, purchase_date, expiration_date
FROM membership_sales
ORDER BY purchase_date DESC;
```
**Результат:** першим іде продаж з `id = 10`, дата придбання — `2026-09-10`. Він опинився першим, тому що `DESC` сортує дати від найпізнішої до найранішої.

### Завдання 2. ORDER BY за кількома колонками
Використано запит:
```sql
SELECT id, membership_id, client_id, purchase_date
FROM membership_sales
ORDER BY membership_id ASC, purchase_date DESC;
```
**Пояснення:** спочатку записи групуються за `membership_id` у порядку зростання. Друга колонка `purchase_date` сортує записи всередині кожної групи від найновішої дати до найстарішої. Отже, друга колонка уточнює порядок рядків, у яких значення першої колонки однакове.

### Завдання 3. Топ-3 через ORDER BY + LIMIT
Використано запит:
```sql
SELECT id, membership_id, client_id, purchase_date
FROM membership_sales
ORDER BY purchase_date DESC
LIMIT 3;
```
**Результат:** отримано три найновіші продажі:
- `id = 10` — `2026-09-10`;
- `id = 9` — `2026-09-09`;
- `id = 8` — `2026-09-08`.

`ORDER BY` має бути перед `LIMIT`, оскільки спочатку потрібно впорядкувати всі записи, а вже потім вибрати перші три. Якщо прибрати `ORDER BY`, команда `LIMIT 3` поверне просто три рядки без гарантії, що вони будуть найновішими.

### Завдання 4. DISTINCT та IN
**а) Унікальні типи абонементів**
```sql
SELECT DISTINCT type
FROM memberships
ORDER BY type;
```
**Результат:** знайдено 6 унікальних типів абонементів: `one-time`, `weekly`, `monthly`, `quarterly`, `yearly`, `student monthly`.

`DISTINCT` прибирає повторення однакових значень у результаті.

**б) Вибір абонементів за списком**
```sql
SELECT id, type, duration_days, price
FROM memberships
WHERE id IN (1, 2, 3)
ORDER BY id;
```
Обрано `IN`, оскільки потрібно знайти записи з конкретним переліком ідентифікаторів: 1, 2 та 3. `BETWEEN` тут менш доречний, бо він призначений для безперервного діапазону значень, а не для довільного списку.

### Завдання 5. LIKE і регістр кирилиці
**а) Пошук прізвищ, що починаються з великої літери «П»:**
```sql
SELECT id, first_name, last_name
FROM clients
WHERE last_name LIKE 'П%';
```
**Результат:** знайдено 1 запис — Петренко.

**б) Пошук прізвищ, що починаються з малої літери «п»:**
```sql
SELECT id, first_name, last_name
FROM clients
WHERE last_name LIKE 'п%';
```
**Результат:** знайдено 0 записів.

Кількість рядків відрізняється, оскільки в SQLite оператор `LIKE` для кириличних символів може бути регістрозалежним. Символи «П» та «п» сприймаються як різні. Це важливо враховувати, оскільки в базі курсу текстові дані переважно українською мовою.

### Висновок
Під час практичної роботи було виконано сортування записів за однією та кількома колонками, отримано три найновіші продажі за допомогою `ORDER BY` і `LIMIT`, визначено унікальні типи абонементів через `DISTINCT`, застосовано `IN` для вибору конкретних записів і перевірено особливості `LIKE` під час пошуку українського тексту. Усі запити виконуються без зміни структури таблиць.
