
### Завдання 1. printf() для числової колонки
```sql
SELECT
    id,
    type,
    price AS raw_price,
    printf('%.2f грн', price) AS formatted_price
FROM memberships
ORDER BY id;
```
**Пояснення:** `%.2f` виводить число з рівно двома знаками після десяткової крапки. Текст `грн` додається до відформатованого значення.

Порівняння сирого та відформатованого значень:
- Сире значення: `150.0`; відформатоване: `150.00 грн`.
- Сире значення: `500.0`; відформатоване: `500.00 грн`.
- Сире значення: `1200.0`; відформатоване: `1200.00 грн`.

Сире значення показує число так, як воно зберігається у таблиці. Форматоване значення зручніше для читання у звіті, оскільки має два знаки після крапки та позначення валюти. `printf()` не змінює саму ціну в таблиці — він змінює лише вигляд значення у результаті запиту.

Завдання 2. printf() з вирівнюванням
```sql
SELECT
    id,
    type,
    printf('%8.2f', price) AS aligned_price
FROM memberships
ORDER BY id;
```
**Пояснення:** `%8.2f` задає мінімальну ширину поля 8 символів і два знаки після крапки. Якщо число коротше, перед ним додаються пробіли. Це допомагає вирівняти значення під час перегляду результату як тексту або експортування у звіт. Ширина є мінімальною: довше значення не обрізається.

Завдання 3. Зсув дати відносно наявної
```sql
SELECT
    id,
    purchase_date,
    expiration_date,
    date(expiration_date, '+30 days') AS extended_expiration_date
FROM membership_sales
ORDER BY id;
```
**Пояснення:** `date(expiration_date, '+30 days')` обчислює дату на 30 днів пізніше за поточну дату завершення абонемента. Практичний сенс — показати, до якої дати абонемент діяв би у разі продовження ще на 30 днів. Це лише розрахунок у результаті `SELECT`; дата у таблиці фізично не змінюється.

Завдання 4. strftime() і GROUP BY за місяцем
```sql
SELECT
    strftime('%Y-%m', purchase_date) AS purchase_month,
    COUNT(*) AS sales_count
FROM membership_sales
GROUP BY purchase_month
ORDER BY purchase_month;
```
**Результат:** усі записи у наявних даних належать до місяця:
- `2026-09` — 10 продажів.

**Пояснення:** `strftime('%Y-%m', purchase_date)` витягує з повної дати рік і місяць. Групування виконується за цим значенням, щоб об'єднати всі продажі одного місяця. Якби групувати за повною датою, кожен окремий день міг би утворити власну групу, тому підрахунок за місяцями був би неправильним для поставленої мети.

### Завдання 5. Свідома помилка з некоректною датою
```sql
SELECT
    'not-a-date' AS invalid_input,
    strftime('%Y', 'not-a-date') AS extracted_year,
    date('not-a-date') AS parsed_date;
```
**Фактичний результат SQLite:** `strftime('%Y', 'not-a-date')` повертає `NULL`, і `date('not-a-date')` також повертає `NULL`. SQLite не завершує запит помилкою.

**Пояснення:** функції дати не змогли розпізнати рядок як коректну дату, тому повернули `NULL`. На таку поведінку не можна покладатися як на автоматичну перевірку введення: некоректний рядок може зберегтися у колонці, якщо для неї не задано відповідних обмежень. Для перевірки формату даних потрібно використовувати належні обмеження, наприклад `CHECK`, і перевіряти значення під час введення.

### Контрольні питання

**1. Чим printf() відрізняється від зміни значення в таблиці?**
`printf()` форматує значення лише для відображення у результаті запиту. Фізичне значення колонки не змінюється, оскільки `SELECT` не оновлює дані.

**2. Чому strftime('%Y', колонка) повертає рік як текст, а не число?**
`strftime()` повертає текстовий рядок. Наприклад, рік `2026` повертається як текст `'2026'`. Це може мати значення під час порівнянь і сортування: текстові значення порівнюються як рядки, а не як числа. Для числових обчислень можна застосувати `CAST(... AS INTEGER)`.

**3. Що результат завдання 5 означає для CHECK-обмежень на дати?**
Не можна вважати, що функція `date()` сама відхилить некоректну дату. Для контролю потрібно явно задати `CHECK`-обмеження, яке перевіряє коректність значення, наприклад `CHECK(date(date_column) IS NOT NULL)` для відповідної колонки, а також за потреби перевіряти формат дати.

Висновок
Під час практичної роботи було відформатовано ціни абонементів за допомогою `printf()` з двома знаками після крапки та заданою шириною поля. За допомогою `date()` було обчислено дату завершення абонемента після продовження на 30 днів. Функцію `strftime()` використано для виділення року й місяця та підрахунку продажів за місяцями. Також перевірено поведінку SQLite з некоректною датою: функції `date()` і `strftime()` повертають `NULL`, а не повідомлення про помилку. Структуру бази даних не змінювали.
